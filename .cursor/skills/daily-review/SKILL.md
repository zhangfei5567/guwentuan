# 每日复盘系统

本技能管理顾问团的每日复盘全流程：记录 → 提炼 → 讨论。

## 模式识别

根据用户意图进入对应模式（用户未说明时，根据上下文推断）：

| 用户意图 | 模式 | 触发词示例 |
|---------|------|-----------|
| 写/补全今日复盘 | **记录** | 复盘、今天做了什么、写复盘 |
| 从已有内容提取要点 | **提炼** | 提炼要点、总结复盘、提取关键信息 |
| 围绕要点深入交流 | **讨论** | 讨论复盘、聊聊今天、帮我分析 |
| 完整流程 | **全流程** | 完整复盘、复盘一下 |

## 记录模式

1. 确定日期（默认今天，格式 `YYYY-MM-DD`）。
2. 读取 `references/template.md` 作为结构参考。
3. 引导用户补充以下内容（用户已提供则直接整理，勿重复追问）：
   - 今日完成
   - 遇到的问题与卡点
   - 收获与认知
   - 情绪与状态（可选）
   - 明日计划
4. 将整理后的内容写入 `reviews/YYYY-MM-DD.md`。
5. 更新 `reviews/INDEX.md`（见下方索引规则）。
6. 简要确认已保存，并询问是否继续「提炼」或「讨论」。

## 提炼模式

1. 定位复盘来源：
   - 指定日期 → 读取 `reviews/YYYY-MM-DD.md`
   - 未指定 → 优先今天，否则最近一次复盘
   - 用户直接粘贴内容 → 以粘贴内容为准
2. 读取 `references/extraction-format.md`，按格式提炼要点。
3. 提炼维度（根据内容取舍，无相关内容则标注「无」）：
   - **核心成果**：今天真正推进了什么
   - **关键问题**：阻碍、失误、未决事项
   - **认知升级**：新理解、反直觉发现
   - **决策记录**：做了什么选择、为什么
   - **行动项**：待办、责任人、优先级
   - **模式信号**：重复出现的行为、情绪或瓶颈（可与历史复盘对照）
4. 将提炼结果写入 `reviews/insights/YYYY-MM-DD-summary.md`。
5. 在原文 `reviews/YYYY-MM-DD.md` 末尾追加「要点摘要」区块（若尚未存在），避免重复追加。
6. 以结构化列表呈现要点，并询问是否进入「讨论」模式。

## 讨论模式

1. 确保已有要点（无则先执行提炼模式）。
2. 读取 `references/discussion-guide.md` 选择讨论策略。
3. 讨论原则：
   - 以用户复盘事实为依据，不臆造
   - 先澄清再建议，先理解再评判
   - 每个观点附带可执行的下一步或验证方式
   - 适度挑战假设，但保持支持性语气
4. 讨论框架（按要点类型选用）：
   - **成果**：价值是否匹配投入？有无更高效路径？
   - **问题**：根因是什么？可控 vs 不可控？类似问题是否出现过？
   - **认知**：如何验证？会改变哪些后续决策？
   - **决策**：备选方案？复盘此决策的评判标准？
   - **行动项**：是否 SMART？与明日计划是否一致？
   - **模式**：跨日复盘的趋势？需要系统性调整什么？
5. 若存在历史摘要（`reviews/insights/` 或 `INDEX.md`），主动关联近期模式。
6. 讨论结束时，询问是否将结论写入 `reviews/insights/YYYY-MM-DD-summary.md` 的「讨论结论」区块。

## 全流程模式

依次执行：记录 → 提炼 → 讨论。每步完成后简要汇报，征得用户同意再进入下一步（用户说「继续」则自动推进）。

## 文件约定

```
reviews/
├── INDEX.md                      # 复盘索引
├── YYYY-MM-DD.md                 # 原始复盘
└── insights/
    └── YYYY-MM-DD-summary.md     # 提炼要点与讨论结论
```

### INDEX.md 更新规则

每次新建或更新 `reviews/YYYY-MM-DD.md` 时，在 `INDEX.md` 表格中追加或更新一行：

```markdown
| 日期 | 关键词 | 状态 |
|------|--------|------|
| 2026-06-08 | 关键词1, 关键词2 | 已记录 / 已提炼 / 已讨论 |
```

关键词从「核心成果」和「关键问题」中各取 1-2 个词。

## 交互风格

- 使用中文，简洁有条理
- 列表和表格优先于长段落
- 不确定时明确标注假设，并向用户确认
- 不替用户编造复盘内容；信息不足时追问而非填充
